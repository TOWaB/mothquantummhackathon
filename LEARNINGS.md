## 2026-09-26

- **A1 ran: 80 fresh flips (two independent 40-flip runs), zero repeats, 36/80 heads (45%).** The earlier "two spins drew the identical 8 bits" observation does not replicate — treat it as small-sample coincidence (1/256 chance, but n=8 is too small to conclude a seeded simulator from one repeat). Lesson: one striking coincidence in a small sample is a hypothesis, not a finding. Full writeup: `docs/findings.md`.
- **Reversed my own earlier flag on `comet-qrng-v1`.** Looked great from its schema (certificate, Bell witness, direct unbiased-integer derivation) — actually tested it, three parameter sizes, all three failed to produce any output (`no conditioned bytes available`), 20 credits spent to learn that. Root cause is in the entropy-accounting fields, not the top-level ones: `emu` mode's `log2(shots!)` ordering penalty outgrows the raw entropy budget. Lesson: a promising `params_schema` is not a working call — run it for real, and read the accounting fields that explain a failure, before recommending an engine change.
- **`.app{min-height:100%}` (lifted from `reference/screen.html`) let the log panel push the whole page to 8862px tall** instead of scrolling inside its own box — confirmed with a real Playwright screenshot before shipping it, not assumed from reading the CSS. `07-design.md` explicitly warns about exactly this trap ("min-height:0 on every flex/grid child with a scroller, or the log will push the page") but the warning only holds if something above actually caps the height — the reference file never needed to, since its log is static/short. Fixed: `height:100%` (a real ceiling) plus `overflow:hidden` on `.app`. Lesson: a static reference page can hide a layout bug that only shows up under real, growing content — render it for real before trusting it.
- **Auto-spin drift silently hijacked the face panel during a live spin.** Nothing stopped the idle drift once a spin started — only `snapTo` at the very end stopped it — so for the entire multi-second wait (flips, mask preview, job), the ambient rotation kept changing which face was "front" and each change fired `onFaceSelected`, overwriting the mask preview and panel with an unrelated random face. Caught by an actual mismatch (a spin landed on face 1, the displayed image was a different face's photo), not by reading the code. Fixed: `dodeca.setAutoSpin(false)` on `spin_start`, not just at landing — the whole live sequence is about one specific face, ambient drift has no business competing with it while it's in progress.
- **The SSE fallback-to-polling path only ever refreshed counters.** If the browser's `EventSource` drops (observed directly, cause unconfirmed — a raw `curl -N` connection stayed open and correct for 100+s against the same server, so this looks like a browser/environment quirk rather than a server bug, but the gap is real either way), the visitor's screen could get stuck on stale "Flipping..." status forever, with only the top counters ticking as a confusing tell that *something* was still happening. Fixed: the fallback now refreshes the full face panel and floor strip too, every 2s, not just counters. Known remaining limitation: it still can't show the *live* mask preview during a rebake, since that's a transient event, not persisted queryable state — acceptable for a degraded fallback mode, not fixed further given time.
- **`.app{height:100%;overflow:hidden}` (the earlier desktop log-scroll fix) broke mobile completely.** On a phone the three columns stack into one, and that same hard height cap just clipped everything below the fold with no way to scroll to it — confirmed with a real iPhone-viewport screenshot (Playwright + `devices['iPhone 13']`) before fixing, not assumed. The desktop fix and the mobile fix are opposites: fixed-height-with-internal-scroll for the 3-column layout, natural-page-scroll with bounded individual boxes once it's one column. Fixed with a `@media(max-width:760px)` override. Lesson: a fix verified on desktop needs re-verifying at the other breakpoint before calling a layout "done" — the same rule can be right at one width and wrong at another.
- **Adding `autoSpin` state exposed a real hit-testing bug that predated it**: the HUD buttons (`#homeBtn`, now `#autoSpinBtn`) live inside `#stage`, and `dodeca.js`'s own `pointerdown` handler calls `stage.setPointerCapture(e.pointerId)` on every press regardless of target — this silently swallows a *real* mouse click on the button underneath (confirmed: a native `el.click()` worked, a real Playwright mouse click did not, until the handler bailed out early for anything inside `.hud`). Likely why "no click works" was reported — probably compounded by this, not just the missing `onFace` wiring.
- **Removing the 2.8s idle-timeout gate on auto-spin exposed a JS temporal-dead-zone crash**: `Dodeca()`'s constructor calls `mark()` synchronously, which fires `onFace` immediately if a face fronts on load — previously this only ever happened after a real animation-frame delay (the old idle-timeout couldn't be true on frame 0), so `onFace`'s callback body was never actually executed until well after the rest of the script had run. Removing that gate meant it now runs *during* `app.js`'s own top-level construction, before later `let`/`const` declarations (`latestState`, `frontFace`, `els`, `ROWS`) had executed — a real `ReferenceError`, not `undefined`, crashing the whole script. Fixed by moving those declarations before `Dodeca()`'s construction. Lesson: a callback that used to fire "later" can start firing "now" the moment its trigger condition changes, and needs the same ordering scrutiny as anything called synchronously at module load.
- **Every regeneration was overwriting the same `faceNN.png`, destroying the previous version's actual image** — only `versions.json`'s metadata survived, not the pixels, so "click a version row, load that version" (TASKS.md D5) was impossible even though the doc's own naming table (`08-structure.md`: `face{NN}_v{N}.png`) already specified the fix. Caught while wiring `versions.py` in, before it shipped. Fixed: every version now writes its own `faceNN_vN.png`, `faceNN.png` stays as a "current" pointer copy.
- **`docs/04-mask.md`'s literal formula would have broken every already-baked face.** Its `m = clamp((d+erode)/radius + 0.5, 0, 1)` uses a different denominator convention than the existing, proven `distance_gradient` (`radius` vs `2*radius`) — same numeric radius, half the transition width. The doc's own regression test ("floor=0 reproduces today's output exactly") is the thing that catches this, if you actually run it rather than trust the formula by eye. Ran it: caught it. Kept the old denominator, added floor/erode around it.
- **`docs/06-copy.md`'s reroll/reblend definitions were inverted** relative to the actual code (checked `app.py` directly, confirmed by testing both paths earlier in the session). The doc's author inferred the mapping from one historical log entry without reading the source. Lesson: when a doc and the code disagree on what a mechanism does, check the code — a doc built from log inference is a hypothesis about the code, not a report of it.

- **Handoff pack's `tools/_atlas.py` used a guessed API shape** (`POST /jobs`, `GET /jobs/{id}`) that doesn't match the real, working API already verified in this repo (`POST /engines/{engine}/process`, `GET /jobs/{id}/status` + `/result`). Never trust a probe script's own client without checking it against one that has actually completed real jobs. Fixed by rewriting the tools to import the real `atlas.py`.
- **Catalog check turned up `comet-qrng-v1`**, a certified-randomness engine (SP 800-90B min-entropy certificate, Toeplitz extractor, CHSH Bell witness, commit-before-outcome) that the handoff's own Q7 didn't know existed. Its docs say emu mode is "uncertified, simulator-baseline" — independent confirmation of the A1 determinism suspicion, from Moth's own engine description.

## 2026-09-25

- **`.gitignore` excluded `out/` and `state/` entirely.** Would have silently dropped every manifest, generated image and the API log from the pushed repo — exactly the proof needed for Expert 01. Fixed: removed both from `.gitignore`.
- **`quantum_choice()` over 12 options costs ~4-9 real `coin-toss-v1` calls** (rejection sampling), ~7-10s each. Picking one face live is 40-90s, not instant. A "quantum pick" being one cheap call does not mean the decision built from several of them is cheap or fast.
- **`coin-toss-v1`'s result includes `backend`/`mode`** (`aer`/`emu`) — it's a simulator by default, not real hardware. `mode: "qpu"` exists but queues minutes to hours per the docs, unusable inside a live interaction.
