## 2. The piece

Concert photographs and public domain classical audio, run through Atlas engines to produce a state that accumulates. Every viewer sees something nobody else has seen, and every viewing changes what the next person sees.

**The concept:** reception of music and image is personal to each listener but culturally shared. The more people who see it, the further it drifts from where it started.

**Why accumulation matters:** "different every time" on its own is noise. If each viewing is independent and random, nothing builds and there is no collective interpretation to point at. Shared state is what makes the cultural claim true rather than asserted.

## 4. Architecture

### The recursive state

State 1 is built from 12 images plus the song. State 2 is built from 12 images plus the song plus state 1. And so on. Each output genuinely contains every output before it, so the drift is real rather than simulated.

### Three instances

The viewer picks 1, 2 or 3. Each instance has its own song and its own independent chain. This cuts chain length per instance and gives visitors a choice at the exhibition.

### The live call, and why it is required

Intermediate 05 requires the web app to call the Atlas API. A fully pre-baked design makes no live calls and would not qualify.

The fix is built into the recursion. A viewer arrives, sees the current state instantly from disk, and their arrival fires a live Atlas call that generates the next state in the background. Nobody waits on a queue, the API call is genuinely live, and the accumulation is the mechanism rather than a decoration.

Pre-fetch a pool of Coin Toss values overnight as a fallback so a slow queue never freezes the screen.

### Daisy chain routing

Intermediate 03 is a maximise game, so route deliberately rather than minimally:

Telablur, Quantum Blur, Qpixl, Tessa Image, Entanglement Shader, QRC Audio, Quantum Echo, Coin Toss.

Eight engines, each justified by the piece rather than bolted on.

### The dodecahedron

A regular solid with 13 faces does not exist. A dodecahedron has exactly 12, which matches the 12 source images.

Twelve faces carry the originals. The rotation resolves into the single generated image. Source and output visible in one object, no caption required.

It claims Beginner 03 only if the surface material is generated by Entanglement Shader, which is a quantum iridescent BSDF generator. That is an engine genuinely applied to a 3D asset. A plain texture swap would not qualify.

## 5. Audio

Composition expiring is not the same as the recording expiring. Mozart is public domain; a 1998 orchestral performance of Mozart is not. Both need to be clear.

1. **Musopen CC0 filter**, musopen.org/search/?license=cc0. Performer has waived rights, no attribution required, modern quality. Free account caps at 5 downloads per day, so download tonight.
2. **Classicals.de**, curated Creative Commons classical, attribution required, cleaner browsing.
3. **Internet Archive pre-1929 recordings**, the recording itself has aged out. Surface noise and narrow range, which may suit what the engines do.

Take option 1. Choose pieces with clear structure and space rather than dense orchestral, because QRC Audio and Quantum Echo will smear anything busy.

## 6. The files

**probe.py** — upload one image, call Telablur with two assets, poll until done, save the result. Answers four unknowns: does the key work, what parameters does Telablur take, how long does one job take, does the material survive.

**generate.py** — builds the recursive chain. Sequential by necessity. Writes numbered PNGs into /out with a JSON manifest recording which Moth job id produced each frame. Converted to a notebook afterwards for Expert 02.

**app.py** — small Flask server. Serves the page, holds the shared state, picks the current frame, fires the live Atlas call, records each view. Around 80 lines.

**index.html** — full-screen image, audio, drift meter, view counter, Moth job id in the corner.

## 7. Known constraints

**Job latency decides the design.** Recursion is sequential and cannot be parallelised, because each state needs the one before it. At 60 seconds per job, 300 states is five hours and works overnight. At three minutes per job it is impossible and chain length drops to about 60 states per instance.

**Compounding degradation.** Feeding output back in repeatedly compounds artefacts. By iteration 20 the result may be mud. Mitigation: weight each new state mostly toward fresh source images with the previous state at roughly 20 percent. Test on five iterations before committing to hundreds.

**Expect rough output.** Encoding a large image into few qubits produces heavy blocking and smearing. Faces break. This is documented in Wootton's own published work and is not a bug to fix.

**Rights on the images.** The festival images need explicit permission from the friend in Romania covering public display, including anything the performers or venue require.

## 9. What to add if there is time

1. **The drift meter.** A visible number showing how far the current state has moved from the original photographs. Moth's previous challenges explicitly rewarded a control parameter that does nothing at zero and scales smoothly. This one is driven by the audience rather than a slider.
2. **The Moth job id on screen.** Small, in the corner. Proves the frame came from their hardware rather than a Photoshop filter, and makes their platform the evidence.
3. **A QR code.** Visitors open it on their own phone and get their own frame, so the piece spreads across the room instead of queuing at one screen.
4. **A reset.** So it can be run from zero for a judge.

## 10. What Moth rewards

From their previous hackathons.

1. Creativity and novelty of the aesthetic result, repeatedly stated as the primary criterion
2. A genuinely quantum-driven mechanism, not quantum as decoration
3. Working, well-coded execution with sensible control parameters
4. Quantum sophistication is not required to win

James Wootton is known for scepticism of demos that only work in the press release. Build something that runs and show live examples.

**Claim the mechanism built, not the one designed.** If shared state does not get finished, say plainly that each frame was fixed by a measurement that cannot be repeated, and that accumulation was not built. A smaller true claim survives that panel. A larger unprovable one does not.
